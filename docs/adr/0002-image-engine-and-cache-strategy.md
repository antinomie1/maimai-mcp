# 2. 图像引擎与内存/多线程并发策略

Date: 2026-08-18

## 状态
已通过 (Accepted)

## 上下文与问题陈述
原 Python 版本使用 PIL 进行图像渲染。重构时需要解决：
1. 像素级绝对坐标对齐（与原图 1:1 吻合）。
2. 避免千张封面常驻内存导致的内存暴涨问题。
3. 高并发和低延迟渲染（尤其是 B50 的 50 张曲目卡片拼接）。

## 决策驱动因素
* **低内存占用**：服务空闲内存 < 15MB，绘制 B50 峰值内存 < 40MB。
* **高响应速度**：B50 生成时间 < 50ms。
* **零系统 C 依赖**：无跨平台 C 库编译障碍。

## 决策结果
* **技术选型**：纯 Rust 组合 `image` + `imageproc` + `ab_glyph`。
* **多线程策略**：采用 `rayon` 并发读取/裁剪 50 首曲目封面并并行合成局部 Tile。
* **内存分层缓存（吸取 Legacy 优点）**：
  1. **UI 静态小图标/边框/背景**：常驻内存（数十张小图，总内存 < 5MB）。
  2. **曲目封面 (`cover/*.png`)**：按需从磁盘读取，配合 OS 文件缓存与 Rayon 并行 IO/解码，不长期霸占几百兆 RAM。
  3. **输出图**：直接编码为 PNG 内存流（Base64）并写入本地 `output/` 临时文件。
