# 3. 弱智能模型容错、自动修复与双轨输出策略

Date: 2026-08-18

## 状态
已通过 (Accepted)

## 上下文与问题陈述
在 AstrBot / QQ 群聊等实际部署场景中，许多接入的 LLM（如 7B/14B、低智能度模型）存在以下痛点：
1. 入参不严谨：容易传入大小写错误（`DivingFish`）、中文难度（“紫/绿”）、浮点定数（`13.5`）或无法准确区分曲名和别名。
2. 异常脆弱：当 MCP 工具返回协议级报错（`is_error: true`）时，弱模型容易复读英文堆栈或胡乱编造假成绩。
3. 平台兼容：QQ 机器人需要灵活兼容 Base64 图片与本地文件路径。

## 决策驱动因素
* **用户体验**：弱模型调用成功率接近 100%，无幻觉、无崩溃。
* **零门槛查分**：只要服务端配置了开发者 Token，仅凭上下文中的 QQ 号即可直出图片。

## 决策结果
1. **Rust 底层入参归一化**：
   - 难度参数自动映射：`"紫" / "master" / "mas" / "3" -> 3`。
   - 查分源枚举不区分大小写，曲名/别名/ID 统一模糊检索与回退。
2. **全局与用户配置优先级**：
   - 显式参数 > 用户配置 (`data/users/<qq>.json`) > 全局开发者凭据 (水鱼+QQ直查)。
3. **友好兜底与弱模型防崩**：
   - 查无数据或未绑定时，以 `is_error: false` 返回结构清晰、带有操作指引的人类可读中文提示。
4. **双轨输出策略 (Dual-Track Output)**：
   - 默认出图模式下，MCP 响应同时包含标准 Base64 Image Content Block、本地持久化图片文件绝对路径（供 AstrBot 快捷发图）以及核心文本摘要。
